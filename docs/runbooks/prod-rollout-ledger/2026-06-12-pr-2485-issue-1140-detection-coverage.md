# 2026-06-12 · PR #2485 · Issue #1140 detection coverage

- **Owner:** prod rollout coordinator
- **Source:** [#2485](https://github.com/layervai/nhp/pull/2485) · [issue #1140](https://github.com/layervai/nhp/issues/1140) · [qurl-service#918](https://github.com/layervai/qurl-service/issues/918) · [follow-up #2493](https://github.com/layervai/nhp/issues/2493)

Adds NHP-owned CloudTrail custom detections, app-level security counters, and CloudWatch alarms for the #1140 detection gap. Not fully validatable in sandbox because sandbox has `enable_cloudtrail = false`; prod apply is the first CloudTrail filter creation. Custom `ticket` alarms still notify the shared `alerts` SNS topic on ALARM; they only omit OK notifications until #2353 splits lower-urgency routing.

- [ ] Pre-rollout: validate the four custom CloudTrail filter patterns with `aws logs test-metric-filter` samples for unauthorized API calls, `UpdateAssumeRolePolicy`, direct `kms:Decrypt` on the secrets CMK, and direct `kms:Decrypt` on the logs CMK. For KMS, include a synthetic direct decrypt whose `resources` array contains the real key ARN and assert the CLI returns at least one match, proving the `$.resources[*].ARN` selector is live before apply; do not proceed with prod apply if this positive-match assertion is skipped or fails. Also include service-principal `invokedBy` samples and role-assumed service-integration samples from the actual NHP secrets/logs CMK paths, especially CloudWatch Logs/CloudTrail reads where `invokedBy` may be absent, so expected service traffic does not false-positive. Confirm the secrets alarm is acceptable at threshold 1 and the logs alarm is acceptable at threshold 5 in 5 minutes.
- [ ] Pre-rollout: capture a recent prod CloudTrail baseline for the unauthorized-API pattern (`AccessDenied*` / `*UnauthorizedOperation`) and confirm the threshold 10/5min ticket alarm is above normal background rates. Raise the threshold before apply if the baseline would have produced repeated ALARM notifications.
- [ ] Pre-rollout: confirm the prod monitoring `alerts` SNS topic (`module.monitoring.sns_topic_arn`) has at least one CONFIRMED subscriber; both CIS and custom CloudTrail alarms fail loud when `enable_cloudtrail = true` without an alerts topic.
- [ ] Pre-rollout: confirm the shared `alerts` topic handling is acceptable for the new ticket-class custom detections. Expected behavior before #2353: ALARM notifications route to the shared topic, OK notifications are omitted, and high-noise ticket separation remains a routing/subscription follow-up rather than a weakened filter pattern.
- [ ] Pre-rollout: tell the rollout owner that `*-custom-update_assume_role_policy` can ALARM during a prod apply that edits IAM role trust policies. The filter intentionally does not exclude the expected CI/deploy role because a compromised deploy role changing trust policy is part of the #1140 threat model. Treat an event from the expected CI/deploy role during the apply as ticket-class apply evidence; investigate any other caller or out-of-window event.
- [ ] Pre-rollout: review the prod Terraform plan for additive-only changes: 4 `aws_cloudwatch_log_metric_filter.cloudtrail_custom_detection`, 4 matching `aws_cloudwatch_metric_alarm.cloudtrail_custom_detection`, 1 server `internal-token-validate-failure` alarm, and 1 AC `aop-replay-detected` alarm.
