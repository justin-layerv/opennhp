# 2026-06-09 · qurl-service #874 · `qurl-webhook-event-dedupe` table

- **Owner:** prod rollout coordinator
- **Source:** [layervai/nhp PR](https://github.com/layervai/nhp/pull/2436) · paired with [qurl-service #874](https://github.com/layervai/qurl-service/pull/874) (closes [#819](https://github.com/layervai/qurl-service/issues/819))

Creates the `qurl-webhook-event-dedupe` DynamoDB table required by the qurl-service schema reconciler in `internal/health/dynamodb_schema.go` (PR #874 added the table to `dbclient.Tables`). Without the table, `DescribeTable` fails, `/health/ready` flips to 503, and ECS rolls every qurl-service deploy back. Sandbox qurl-service has been frozen on task def `:635` (commit `ad3adb6`, 2026-06-07) since 2026-06-09 03:28 for exactly this reason.

- [ ] Pre-rollout (prod): `terraform apply` of this PR's plan against `terraform/environments/prod/` succeeds and `aws dynamodb describe-table --table-name layerv-nhp-prod-cell0-qurl-webhook-event-dedupe --region us-east-2` returns `TableStatus=ACTIVE` BEFORE the qurl-service prod image promotes past commit `08cc47f`. NOTE: the `qurl-schema-check` gate in promote-to-prod walks `requiredIndexRequirementsFromRegistry()` and only flags missing GSIs/projections; the dedupe table has no GSIs, so schema-check does NOT block on its absence. The runtime reconciler does (`/health/ready` 503 → ECS rollback) — that's the actual gate.
- [ ] Post-rollout (sandbox): re-run the failing qurl-service sandbox deploy. `aws ecs wait services-stable` succeeds, the new task def reaches RUNNING and a steady state past `:635`, `/health/ready` returns 200 on the new task, and `journalctl -u qurl-service` shows no `dynamodb schema drift detected on startup` errors mentioning `qurl-webhook-event-dedupe`.
- [ ] Cross-repo: SQS queue provisioning + `WEBHOOK_EVENTS_CONSUMER_ENABLED` + `WEBHOOK_EVENTS_SQS_QUEUE_URL` task-env wiring stay in a separate follow-up — out of scope here. This PR only unblocks the schema-reconciler-side prerequisite. The runtime consumer goroutine stays dormant on default config.
- [ ] Rollback: if the table apply causes any unexpected fallout, leave the table in place and disable `QURL_SCHEMA_RECONCILER_ENABLED` on the qurl-service task — the reconciler is the fail-closed mechanism that surfaces the missing table; muting it restores the prior (broken-but-not-failing-readiness) behavior. The table itself has `deletion_protection_enabled = local.is_prod` so `terraform destroy` will refuse in prod.
