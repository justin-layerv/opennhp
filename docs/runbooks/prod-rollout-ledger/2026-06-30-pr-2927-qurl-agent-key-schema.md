# 2026-06-30 · PR #2927 · qURL agent-key schema guardrails

- **Owner:** prod rollout coordinator
- **Source:** nhp#2927, nhp#1952, qurl-service#1059

Ships nhp-server reader guardrails for the cross-repo `qurl-agent-keys` table:
schema-version gating via base-row `GetItem`, fail-closed distinct-owner
pubkey-collision handling, same-owner re-bootstrap duplicate tolerance, and
narrower read IAM.

- [ ] Pre-rollout: confirm the target environment's qurl-service image includes qurl-service#1037 before deploying this reader, so new distinct-owner duplicate pubkey writes are blocked before nhp-server rejects collision reads. qurl-service#1037 still permits the same owner to register one public key under multiple `agent_id` rows; nhp-server treats that as one unambiguous principal.
- [ ] Pre-rollout: scan `qurl-agent-keys` grouped by `public_key`, reconcile any distinct-owner duplicates before enabling the fail-closed reader, and clean stale/orphan or rotated-key same-owner duplicates as data hygiene. Record confirmation that no public key maps to more than one active `owner_id`, and that no current same-owner sibling has an unsupported `schema_version` that would strand the whole pubkey fail-closed.
- [ ] Pre-rollout: keep the 16-row same-owner inspection cap unless the rollout owner has also reviewed the shared 5s DynamoDB resolve budget. The reader spends that single budget across the `pubkey-index` `Query` plus every same-owner base-row `GetItem`; raising the cap without revisiting latency headroom can convert a data-hygiene problem into repeated uncached retry-after rejects.
- [ ] Rollout: apply the IAM/table policy update and nhp-server image together; the new policy keeps `GetItem` + `Query` for the same table/index path before removing the old broad qurl-agent-keys read resources.
- [ ] Rollout: add or confirm a temporary rollout dashboard/alarm view for `MetricAgentLookupPubkeyCollision`, `MetricAgentLookupPubkeyCandidateOverflow`, `MetricAgentLookupSchemaMismatch`, `MetricAgentLookupDDBError`, and `MetricAuthFailure` before sending first-resolve traffic; use rate/threshold alarm sizing rather than page-on-first-sample noise, while still treating any reviewed collision/schema/overflow sample as data or rollout drift that needs reconciliation.
- [ ] Post-rollout: watch those metrics during first-resolve traffic; any non-zero collision/schema/overflow value means reconcile data or writer rollout before continuing, while a short `MetricAuthFailure` spike with no collision/schema/overflow/DDB error may indicate stale GSI convergence and should self-heal on retry. If `MetricAgentLookupSchemaMismatch` fires, query the affected pubkey's same-owner siblings and repair or remove the unsupported-schema sibling named in the log; that `agent_id` can be the bad sibling rather than the row the agent was successfully using before cold resolve. A planned cross-owner key reassignment can briefly surface both old and new GSI projections, causing a fail-closed reject plus a one-shot `MetricAgentLookupPubkeyCollision` sample until the GSI converges; note any planned reassignment in the rollout log before treating that sample as an incident. `MetricAgentLookupPubkeyCollision` intentionally wins over `MetricAgentLookupPubkeyCandidateOverflow` when the same GSI page is both cross-owner and over-cap, so treat overflow as the same-owner or uninspected-page ambiguity signal, not as a complete count of every `public_key` partition with more than 16 projected rows.
- [ ] Cross-repo: land qurl-service#1059 so new writer rows import the shared schema contract and write `schema_version=1`; until then, nhp-server accepts missing `schema_version` as legacy version 0.
- [ ] Cross-repo: for any future incompatible `schema_version` bump, deploy nhp-server support before qurl-service emits the new version; writer-first order causes uncached schema-mismatch rejects, so affected agents pay `Query` + `GetItem` on every cold knock until the reader catches up or data is reverted.
- [ ] Rollback: revert nhp#2927 or roll back the nhp-server image; old readers resume legacy collision admission and do not require data migration.
