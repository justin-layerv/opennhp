# 2026-06-14 · PR #2551 · qurl-reverse-tunnel-server ASG launch-readiness gate

- **Owner:** prod rollout coordinator
- **Source:** [#2551](https://github.com/layervai/nhp/pull/2551) · tracking [#2548](https://github.com/layervai/nhp/issues/2548) · origin [qurl-reverse-tunnel-server#195](https://github.com/layervai/qurl-reverse-tunnel-server/issues/195) · symptom fix [qurl-reverse-tunnel-server#194](https://github.com/layervai/qurl-reverse-tunnel-server/pull/194)

Adds an `EC2_INSTANCE_LAUNCHING` lifecycle hook (blue + green) so a refreshed/launched frps instance reaches `InService` only after FRP is serving and Cloud Map registered. user_data signals **only CONTINUE** (on a healthy boot); every failure path exits unsignaled and falls through to the hook's `default_result` at `heartbeat_timeout`. Ships with `frps_launch_readiness_default_result = "CONTINUE"` (safe — no explicit ABANDON anywhere, so a broken image can't loop a steady-state scale-out into ABANDON→relaunch); the `ABANDON` flip and prod roll happen via the phased validation below. **Sandbox first.**

**Tracked design decision — resolve before the ABANDON flip (cr-flagged ×3):** user_data resolves its own ASG name via `aws autoscaling describe-auto-scaling-instances`, which needs `autoscaling:DescribeAutoScalingInstances` on `*` (the action has no resource-level support; `CompleteLifecycleAction` is already scoped to the two literal `${name_prefix}-frps[-green]` ARNs). The lower-privilege alternative derives the name from the already-validated `DEPLOY_COLOR` IMDS tag + those deterministic names. Two reasons to adopt it before flipping to `ABANDON`: (1) it drops the `*` grant (the policy's only wildcard); (2) **it removes a happy-path failure mode** — under `ABANDON`, a transient `describe` throttle/hiccup on a *healthy* box falls through to ABANDON and kills a good instance, whereas a local IMDS-tag read has no cross-service dependency. The current cut keeps describe because the alternative adds main-flow boot bash PR CI can't exercise (only `bash -n`/`shellcheck`, not logic), it's plan/shellcheck-validated today, and the `*` only matters under `ABANDON` (Phase 2); it also has in-module `*` precedent in `CloudMapListServices`. **Adopt the DEPLOY_COLOR derivation before the ABANDON flip unless the sandbox run shows `describe` is reliable enough on the happy path.**

- [ ] Pre-rollout (sandbox, CONTINUE default): `terraform apply` + instance refresh; confirm a booting instance sits in `Pending:Wait` (not `InService`), and `user_data` emits CONTINUE **before** `heartbeat_timeout` (an active signal, not a timeout fallthrough) — `complete-lifecycle-action ... CONTINUE` in `/var/log/user-data.log`. **Internalize that Phase 1 (CONTINUE) fixes only the normal still-booting race and gives NO broken-image protection** — a broken image via instance-refresh times out → CONTINUE → `InService`, the refresh "succeeds" with dead boxes, and `auto_rollback` does NOT fire (EC2 health passes). Broken-image protection arrives only with the Phase-2 ABANDON flip.
- [ ] Pre-rollout (sandbox): measure real cold-boot time **from instance launch** (the whole user_data — apt, AWS CLI, container image pull (dominant), readiness, registration); set `frps_launch_readiness_heartbeat_timeout` from data with a **generous** margin (size for worst-case cold cache / ECR throttling, not median — under `ABANDON`, a healthy-but-slow boot that overruns gets killed and can read as a broken image to `auto_rollback`). Default 600 is a placeholder, not a validated value. This timeout is also the latency before a broken boot resolves to `default_result`. Escalation lever if `ABANDON` tuning proves twitchy: emit one `autoscaling:RecordLifecycleActionHeartbeat` after the image pull to decouple the timeout from worst-case pull time (one extra IAM action, same two-ASG scope) — deliberately omitted now to keep the first cut simple.
- [ ] Rollout (sandbox, flip to ABANDON): set `frps_launch_readiness_default_result = "ABANDON"`; force a broken FRP boot (e.g. a bad image tag) → confirm the instance falls through to `default_result=ABANDON` at `heartbeat_timeout` (replaced, not left `InService`) and instance-refresh `auto_rollback` fires (EC2 health alone cannot detect a dead FRP — this is the whole point of ABANDON). Also confirm a broken image in a **steady-state scale-out** (no refresh) does not loop. **Do NOT trigger the first ABANDON refresh in the same window the `CompleteLifecycleAction` grant first lands** — IAM eventual consistency (~60s; see terraform/CLAUDE.md "IAM eventual-consistency shim") could ABANDON early healthy boots before the grant propagates. The CONTINUE-first phase already keeps the grant live for a full cycle before the flip.
- [ ] Rollout (sandbox): confirm the routing-gate premise still holds — `user_data` waits for the readiness probe before `cloudmap-register.sh`, so DNS never resolves to a not-ready box.
- [ ] Rollout (prod): apply with `ABANDON` after sandbox is green; confirm a normal refresh gates `InService` on readiness with no deploy stall (interaction with `min_healthy_percentage=100` / `instance_warmup=180`). Per-instance gating now grows to ~`heartbeat_timeout + instance_warmup` (CONTINUE arrives before `InService`, then warmup counts) — verify deploy/smoke/CI step timeouts (this repo's promote/refresh workflows + the cross-repo qurl-reverse-tunnel-server smoke) accommodate the longer window.
