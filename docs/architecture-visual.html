System Overview

The Problem

Traditional security exposes services to the internet, relying on authentication after connection. Attackers can scan, probe, and exploit vulnerabilities before auth even happens. VPNs create broad network access and management overhead.

LayerV Solution

Resources are invisible by default—all ports appear filtered. Users must cryptographically authenticate before the network path opens. No scanning, no probing, no pre-auth exploitation. Access is per-user, per-session, time-limited.

Use Cases

🏢

Internal Applications

Protect admin panels, internal tools, and dashboards without VPN complexity. Users authenticate via SSO, resource becomes visible only to them.

🔌

API Protection

Hide APIs from scanners and bots. Only authenticated partners/clients can even see the endpoint exists. Eliminates API abuse and scraping.

☁️

Multi-Cloud Access

Unified access layer across AWS, GCP, Azure, on-prem. Users don't need to know where resources live—LayerV handles routing.

🏥

Compliance-Sensitive

Healthcare, finance, government. Data never touches LayerV in Hybrid mode. Audit logs for every access. Meet HIPAA, SOC2, FedRAMP requirements.

Key Architectural Decision: UDP-Only Control Plane

All protocol messages use UDP only. No TCP in the control plane. This eliminates handshake overhead and connection state, enabling stateless horizontal scaling and NAT traversal.

Core Components

🖥️

NHP Server

Receives knock requests via UDP, validates credentials, and instructs ACs to add iptables rules. Stateless and horizontally scalable. HTTP 8888 is for plugin endpoints only.

🛡️

Access Controller (AC)

Runs alongside protected resources. Manages iptables/ipset rules to grant or revoke network access. Always dials OUT to servers.

All components span 3 availability zones. Auto Scaling Groups maintain desired capacity. No single point of failure.

Compute layer has no direct internet access—outbound via NAT only. Data layer is fully isolated with VPC endpoints.

Protocol Messages

All messages are UDP packets with cryptographic authentication. The protocol has three message categories:

User Access

KNK → ACK

User sends knock, server responds with success/fail

AC Registration

AOL → AAK / ARD

AC announces online, server acknowledges or redirects to assigned server

Access Control

AOP → ART

Server instructs AC to open port, AC reports result

Server Mesh

FWD → FRT

Servers forward knocks to the server connected to the target AC

Security Model

🔒

Zero Trust

Resources are invisible by default. All ports appear filtered until cryptographic authentication succeeds.

🔑

Curve25519 Crypto

All NHP communication uses Curve25519 keypairs with Noise protocol for forward secrecy.

🛡️

Network-Level Protection

iptables/ipset rules at the kernel level, not just application authentication.

⚡

Failopen Safety

If control plane fails, access is allowed—no lockout risk for legitimate users.

Key Security Properties

1
AC Private Keys Never Leave Instance

Private keys stored in Secrets Manager, read only by the AC instance. Never in etcd or DynamoDB.

2
AC Initiates All Connections

Servers never connect to ACs. ACs dial out, enabling NAT traversal and reducing attack surface.

3
License-Based Trust (Cloud Mode)

ACs authenticate via bcrypt-hashed license keys validated against DynamoDB. No pre-shared certificates.

4
Constant-Time Validation

License validation uses constant-time comparison to prevent timing attacks.

Key Takeaways

🎯 Core Value

Eliminate attack surface entirely. Resources are invisible until authenticated—no ports to scan, no endpoints to exploit.

⚡ Architecture

UDP-only control plane, stateless servers, ACs dial out. Scales to 100K+ protected resources with sub-50ms latency.

🔧 Flexibility

Three deployment modes: All SaaS (fully managed), Hybrid (data stays local), On-prem (air-gapped). Same protocol, same experience.

✅ Production Ready

Multi-AZ, auto-scaling, DynamoDB global tables. No single points of failure. Battle-tested infrastructure.
